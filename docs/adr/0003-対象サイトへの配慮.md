## 背景

自動収集は対象サイトに負荷をかけ、規約違反や業務妨害と受け取られるおそれがある。また、取得に失敗したことを「商品が無くなった」と誤って通知すると、利用者の判断を誤らせる。

## 決定

| 場面 | 扱い |
|---|---|
| robots.txt が取得できた | 記載に従う。禁止されたページは取得しない |
| robots.txt が無い（404 など 4xx） | 制限なしとして扱う（一般的な解釈） |
| robots.txt が一時的に取得できない（5xx・通信エラー） | そのサイトの収集を今回は見送る（安全側） |
| 取得の間隔 | 設定の間隔と Crawl-delay の長い方。設定の下限は 0.5 秒 |
| 混雑の応答（429・503） | Retry-After があればその秒数（上限 60 秒）、無ければ間隔を倍々に広げて再試行 |
| 恒久的なエラー（404 など 4xx） | 再試行しない |
| 一部のページが取得できなかった | その実行は「一部失敗」とし、掲載終了の判定を行わない |
| ページ送りが終わらない | 取得ページ数の上限で止める。同じ URL は 2 回取得しない |
| 他のサイトへのリンク | たどらない（開始 URL と同じホストのみ） |

※ 「robots.txt が無い（404 など 4xx）」の行は ADR-0005 で変更した（制限なしとするのは 404・410 だけ。それ以外の 4xx は見送る）。商品が 0 件になった回の扱いも ADR-0005 で追加した。

## 理由

- 判断に迷う場合は、取得しない側・通知しない側に倒す方が、対象サイトにも利用者にも害が少ない
- 名乗りに連絡先を入れることで、対象サイトから停止の依頼を受けられる

## 影響

- robots.txt が不安定なサイトでは収集が見送られることがある。見送りはログと履歴に残る
